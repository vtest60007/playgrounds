# 📘 Software Requirement Specification (SRS)  
**Project**: DocConnect Application  
**Version**: 1.0  
**Date**: August 25, 2026  

---

## 1. Introduction
### 1.1 Purpose  
The purpose of the DocConnect application is to provide users with an efficient way to search for doctors based on specialization, gender, city, and locality. It also allows listing all doctors or filtering by category and gender.

### 1.2 Scope  
DocConnect is a web-based application that enables users to:  
- Search for doctors using multiple filters.  
- List all doctors irrespective of filters.  
- Browse doctors by specialization.  
- List all women doctors.  

The system validates user inputs and provides appropriate error messages for invalid data.

### 1.3 Assumptions and Dependencies  
- Database contains valid doctor records for Chennai, Coimbatore, and Madurai.  
- Specialization values are limited to *No Preference, Cardiology, Orthopedics*.  
- Application requires a stable internet connection.  

---

## 2. Functional Requirements
### 2.1 Find a Doctor
- **City (List Box)**: Must allow selection of Chennai, Coimbatore, or Madurai.  
- **Specialization (List Box)**: Options → No Preference, Cardiology, Orthopedics.  
- **First Name (Textbox)**:  
  - Accepts alphabetic values only.  
  - Maximum length = 30 characters.  
  - Mandatory field.  
- **Last Name (Textbox)**:  
  - Accepts alphabetic values only.  
  - Maximum length = 30 characters.  
  - Mandatory field.  
- **Locality (Textbox)**:  
  - Accepts alphabetic values only.  
  - Mandatory field.  
- **Gender (Radio Button)**: Options → Male, Female, Both.  
- **Search (Button)**:  
  - Valid input → Lists all and near matches.  
  - Invalid input → Shows error messages in a pop-up.  

### 2.2 Additional Buttons
- **List All Doctors**: Lists all member doctors irrespective of filters.  
- **Browse By Category**: Lists doctors by specialization irrespective of filters.  
- **List All Women Doctors**: Lists all women doctors irrespective of filters.  

---

## 3. Non-Functional Requirements
- **Usability**: Simple, intuitive UI with clear labels and error messages.  
- **Performance**: Search results should be displayed within 2 seconds.  
- **Reliability**: Application must handle invalid inputs gracefully.  
- **Security**: Input validation to prevent injection attacks.  
- **Compatibility**: Must run on modern browsers (Chrome, Edge, Firefox).  

---

## 4. Validation Rules
- Mandatory fields: First Name, Last Name, Locality.  
- Alphabetic-only input for First Name, Last Name, Locality.  
- Maximum length restriction (30 characters) for First Name and Last Name.  
- Dropdowns must only allow valid database values (City, Specialization).  
- Gender must be selected before search.  
- Error messages must appear in a pop-up for invalid inputs.  

---

## 5. Constraints
- Limited to three cities (Chennai, Coimbatore, Madurai).  
- Limited to two specializations (Cardiology, Orthopedics).  
- No support for partial numeric/alphanumeric names.  

---

## 6. Future Enhancements
- Expand city and specialization lists.  
- Add advanced filters (experience, availability, consultation fees).  
- Integrate appointment booking system.  
- Provide mobile app version.
